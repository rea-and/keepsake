### E. Usability and accessibility

- E1 (M/S): opening a modal focuses the close button instead of the first field (`useDialog.ts:12`), so "press `n`, type a URL" types nowhere.

## Product improvements

Grouped into five themes so the work stays coherent. Each builds on something the code already half-supports.

1. **Capture you can trust.** Saving an already-saved page should enrich it, never reset it (A1). The extension shows a badge for pending and conflicting saves with a review list, and stops retrying permanent failures. Android queues new bookmarks and shares offline (today only edits are queued). The web app gets a PWA manifest with a share target; `App.tsx:68` already handles `?url=`.
2. **Account and devices.** A "Devices" list in Settings backed by the existing session store (label, last used, revoke). Sign-out and "Signed in as…" in the extension. A re-login prompt on Android and in the web app whenever any request returns 401. Sign-out clears local data everywhere.
3. **Library hygiene.** A tag manager (rename, merge, delete) instead of `window.prompt`; a duplicates view; a broken-link checker using the existing SSRF-safe scraper fetch; exact tag matching (`tag:dev` currently matches "devops") and `-tag:`; parent collections include their children; counts on custom collections.
4. **Everyday use.** Visible actions on touch, correct modal focus, a `?` shortcut overlay with j/k navigation, import progress with cancel and honest error styling, a server "last synced" indicator, Android search over notes and descriptions, a notes field in Android's Add sheet.
5. **Operations.** Daily rotating backups of `store.json`, a real version and build id in `/api/health`, working TLS examples for Caddy and nginx, and a reproducible non-root Docker image.

## Technical plan

Five phases, each shippable on its own. Every phase ends with the `keepsake-release` skill (tests, `npm run build`, committed `dist/`).

### Phase 0: sign-in regressions (S, do first)

- **B1:** in `apps/web/src/main.tsx`, attach the bearer to all same-origin `/api/` requests (the public routes ignore it). Add an integration assertion that a session is rejected after `POST /api/auth/logout` sent through the same header logic.
- **B2:** require `apiToken` in the stored-session checks (`useStore.ts:87`, `LoginScreen.tsx:40`).
- **B3:** clear `apiToken` when the server origin changes (`popup.ts` save and sign-in handlers; Android `showServerConfigDialog`).
- **B4:** `acceptExtensionSignIn` returns a reason; `content.ts` relays a negative acknowledgement; the callback page in `auth.ts` shows "Set the extension's server URL to `<origin>`".
- **B5:** store `email` beside `apiToken`; add a "Signed in as … / Sign out" row in `popup.html` that calls `/api/auth/logout` via `apiFetch` and removes the token.
- **B7:** web `logout` also removes the library cache, Drive flag and reader positions; Android sign-out deletes the cache and pending-queue files.
- **B10:** move an unreadable `sessions.json` aside (`.corrupt-<timestamp>`) before the first write; prune on startup.
- **B11:** load `.env` from the repo root as well as the working directory; confirm by running `npm run dev:server`.
- Correct the README/SETUP sentence about sign-out only once B1 ships.

### Phase 1: data integrity (M)

- **Shared validation** (new `packages/shared/src/validate.ts`, exported from `index.ts`): `sanitizeBookmarkInput`, `sanitizeCollectionInput`, `isHttpUrl`. Types are checked, unknown keys dropped, URLs limited to http/https, strings length-capped. Make `normalizeUrl` total (non-string returns `''`). Used by server routes, `serverStore.merge`, `parseNetscapeHtml` and `parseBackup`.
- **A1/A2:** `addOrUpdateBookmark` (`apps/server/src/store.ts`) ignores `undefined` fields. Add a `mode: 'capture'` option: for an existing bookmark it fills only empty metadata (title if sparse, cover, description, favicon) and leaves collection, tags, note, star and done untouched. Extension quick-save paths and HTML import use capture mode. The popup's explicit Save keeps full-update semantics but seeds its form from the saved bookmark (A10).
- **A3/A9/C10:** an `asyncRoute` wrapper for async handlers; the error middleware maps body-parser errors to 400/413 with generic text.
- **A4:** `/api/sync` and `/api/import` run payloads through the validators and `parseBackup`; on load, `store.ts` writes a backup, then drops or repairs malformed records.
- **A8:** in `serverStore.merge`, clamp incoming timestamps to server time plus five minutes, ignore tombstones for system collections, and reassign bookmarks of deleted collections (reuse the logic at `store.ts:373-382`).
- **A12:** decode entities in `parseNetscapeHtml`; skip `place:` and non-http entries.
- **A13:** coalesce writes (short debounce with flush on shutdown, compact JSON) and keep seven daily snapshots under `data/backups/`. Keep the atomic-replace behaviour covered by `apps/server/test/store.test.mjs`.
- **A14:** enrichment writes with `touch: false` so `updatedAt` is unchanged.
- **A5/B6 (Android):** `sendOperation` returns an outcome: success, retry later (network, 5xx), drop (400/404/409/410/422, counted and reported in a toast), or re-login (401, which clears the token and shows the login view with a message). `ShareActivity` uses the same handling.
- **A6/A7/A11 and the fetch-inside-updater calls:** functional `setStore` merges in `useStore.ts`; separate `note` from `description` in the Android edit dialog.
- **Tests:** re-save preserves organisation; non-string and malformed payloads return 400 and the process survives; HTML round trip; tombstone guards; Android unit test for queue outcomes.

### Phase 2: security hardening (M to L)

- **C1/C5:** one-time code exchange for Android. The app generates a verifier and opens `/api/auth/google/url?state=android.<challenge>`. The server sets a short-lived httpOnly state cookie on `/google/url` and verifies it in the callback for all flows (exact flow match, no `includes`). For Android the callback stores `{challenge, email}` under a random single-use code (60 s, in memory) and redirects to `keepsake://auth?code=…`. The app calls a new public `POST /api/auth/exchange {code, verifier}` and receives `{user, apiToken}` only. The app accepts a code only while it holds a pending verifier. Google tokens are no longer sent to Android or written to the browser in that flow.
- **C4:** keep the Google refresh token server-side with the session; `/auth/refresh` requires a session and uses the stored token; the web app holds only the short-lived access token. Requires a re-sign-in.
- **C2:** DOMPurify in `ReaderModal.tsx` (memoized) and with the existing `jsdom` in `scraper.ts`, with an http/https/mailto allow-list; sanitize `readerContent` on every write path; remove the fail-open `catch`.
- **C3:** scheme validation from Phase 1 plus a `safeHref` helper used by the four views.
- **C6:** CSP (`default-src 'self'`, images from any https source, Google APIs in `connect-src`, a per-response nonce for the callback pages' inline scripts), HSTS when the request is https, drop `X-XSS-Protection`.
- **C7:** exclude preferences from Android backup (data-extraction rules); send the token over plain HTTP only to loopback and private addresses, otherwise require https (check in `ApiAuth.kt`); WebView debugging only in debug builds.
- **C8:** static content-script match for Reddit only; request the configured server's origin as an optional host permission at sign-in and register the sign-in bridge for it with `chrome.scripting`. Verify on Firefox before shipping; this is the riskiest extension change.
- **C9/C10:** `textContent` for tag chips; extend the SSRF block list; plain-text auth errors; default CORS to same-origin; a small in-memory limiter on `/api/auth/*`.
- **Tests:** sanitizer vectors, state-cookie mismatch, code replay and wrong verifier, exchange expiry.

### Phase 3: sync and performance (M to L)

- **D1/D5:** the server keeps a monotonically increasing `revision`, returned by `/api/sync` and as an `ETag`; `GET /api/sync` honours `If-None-Match` with 304. The web app pushes only when its store is dirty (debounced), polls with the ETag only while visible and signed in, and guards against overlapping requests.
- **Article text out of the sync payload:** `GET /api/bookmarks/:id/reader` plus a `hasReader` flag; sync and list responses omit `readerContent` unless `?include=reader`. Ship the server first with the old behaviour as default, move web, then Android, then flip the default.
- **D2:** move the library cache to IndexedDB behind a small async wrapper; keep localStorage for preferences and the session; guard every remaining write.
- **D3/D4:** virtualize the four views (`@tanstack/react-virtual`), memoize rows, debounce search, precompute a lowercase search index per bookmark, memoize reader sanitization.
- **Tests:** ETag/304 integration test; extend `apps/web/test/offline.test.mjs` for the IndexedDB cache.

### Phase 4: product features (each S to M, independent)

- **Devices:** store `label` (client type plus user agent summary) and `lastUsedAt` per session; `GET /api/auth/sessions` and `DELETE /api/auth/sessions/:id` (id is a short prefix of the hash); list in `SettingsModal.tsx`.
- **Global 401 handling (B8/B9):** the fetch wrapper raises one "session expired" event; the store shows the sign-in prompt and pauses background work; a `storage` listener signs other tabs out.
- **Extension:** pending/conflict badge and review list (data already in `keepsake_pending_capture_*`), stop retrying 4xx, Ctrl+Enter to save, first-run setup instead of the localhost default, tag autocomplete from `GET /api/tags`.
- **Android:** offline queue for creates and shares, search over note and description, notes field in the Add sheet, sync status row.
- **Tags and hygiene:** `GET /api/tags`, `POST /api/tags/rename`, `DELETE /api/tags/:tag`; tag manager and duplicates view in the web app; link checker as a server job reusing the scraper's guarded fetch, surfaced as a "Broken" filter; exact tag match and `-tag:` in `packages/shared/src/search.ts`.
- **UX fixes (E1 to E4):** focus the first field in `useDialog.ts`; always-visible actions under a coarse pointer; popovers closable by Escape and outside click; accessible names; login error feedback; import progress and cancel; corrected copy; render notes as sanitized Markdown or relabel the field.
- **PWA:** `manifest.webmanifest` with a share target pointing at `/?url=`.

### Phase 5: deployment (S)

- Caddyfile with a real domain block and automatic TLS, plus an optional Caddy service in compose; nginx example with TLS and `X-Forwarded-Proto https`.
- Compose and healthcheck read `PORT`; Dockerfile copies the lockfile, uses `npm ci`, runs as a non-root user.
- `deploy.sh`: skip npm in Docker mode; check `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` as well as the allow-list.
- `keepsake.service`: journal output, `NoNewPrivileges`, `ProtectSystem=strict` with `ReadWritePaths` for `data/`.
- `/api/health` reports the package version and git commit.

### Suggested order

Phase 0, then Phase 1, then the C1/C2/C3 items of Phase 2, then D1, then the rest by preference. Phases 0 and 1 remove every known way to lose data or silently stop syncing.

- C8 (narrower extension host permissions): cannot be checked on Firefox from here, and a wrong change would silently break sign-in.
- D2 (IndexedDB cache) and D3 (list virtualization): large changes to verify visually; the quota fallback and search/sort fixes cover the worst cases for now.
